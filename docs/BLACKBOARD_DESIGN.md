# blackboard 黑板架构设计

> 状态：历史设计基线（Draft 2，0.3.0；不代表当前实现清单）
> 面向版本：`blackboard` 0.3+  
> 核心定义：`blackboard` 是 Agent 的外置黑板，不是约束 Agent 行为的工作流引擎。

> 当前实现以 `AGENT.md`、README 和 [本轮能力与验收](ITERATION.md) 为准。本文后面的旧版路线图、四视图草案与迁移设想仅作历史记录；当前是三视图、多个 Agent 独立视角、显式接入与手动命名迁移。新增字段/操作沿用 eventVersion 1，未新增自动迁移。

## 1. 一句话定义

Agent 自由探索、自由跳转、自由建立逻辑；`blackboard` 只负责把 Agent 留下的节点、关系、当前位置和历史轨迹持久化，并持续呈现在一张可缩放的大图上。

```text
Agent 负责思考和移动
          ↓
blackboard 记录「写了什么、它们如何相关、Agent 现在在哪里」
          ↓
人和后续 Agent 从黑板恢复现场
```

黑板的价值不是告诉 Agent 下一步该做什么，而是让思考过程在上下文压缩、会话切换和多人协作后仍然可见、可恢复、可继续。

### 1.1 统一命名与升级边界

项目正式名称、npm 包名和唯一 CLI 都是 `blackboard`，入口为 `bin/blackboard.js`；事件目录统一使用 `.blackboard/`，其中 `.blackboard/events.jsonl` 是唯一事实源，环境变量只读取 `BLACKBOARD_*`。端口优先级为 `--port` > `BLACKBOARD_PORT` > 项目配置 `viewerPort` > 默认 `4333`。

这是 breaking cutover：不再保留 `flow` 入口、`FLOW_*` 环境变量或 `.flow/` 目录回退，也不提供自动迁移或旧 Skill 退役逻辑。本仓库既有数据原样迁到 `.blackboard/`；其他项目应停止写入、备份后手动重命名目录（不要覆盖已有目标），更新命令与环境变量，手动移除旧 Skill/Hook 并重新安装当前接入，最后重启服务和 Agent 会话。具体命令见 README「项目标识与升级」。节点、关系、游标和事件语义不因命名切换而改变，历史事件无需改写。

## 2. 问题与目标

长链路任务中，Agent 会不断产生目标、观察、猜测、行动、结果、反例和新问题。仅靠对话上下文会遇到四个问题：

1. 上下文压缩后，当前工作位置丢失；
2. 已验证、未验证和已否定的信息混在一起；
3. 分支、回跳和跨分支关系难以从线性对话中恢复；
4. 人只能看到最终回答，无法看到探索空间正在怎样展开。

`blackboard` 的目标是：

- 把关键思考外化成逻辑节点；
- 把节点之间的关系外化成逻辑边；
- 独立记录 Agent 的当前节点和移动轨迹；
- 持续展示完整黑板，并突出当前局部；
- 在上下文恢复时还原现场，而不是替 Agent 做决策；
- 支撑数千到数万节点的长期任务。

### 2.1 非目标

`blackboard` 不负责：

- 规定固定的审计步骤；
- 强制节点必须按某种顺序出现；
- 根据状态机决定 Agent 下一步；
- 把每一次工具调用都提升为逻辑事实；
- 把图整理成一棵没有交叉关系的树；
- 代替任务执行器、编排器或权限系统。

## 3. 设计思想

### 3.1 黑板优先，而不是流程优先

流程系统的问题是先定义合法路径，再要求 Agent 沿路径运行。黑板系统相反：Agent 先行动，黑板随后忠实记录。

因此：

- 节点类型提供语义提示，不构成状态机；
- 边类型表达逻辑关系，不构成合法性约束；
- 当前节点表示注意力位置，不表示结构父节点；
- 创建节点、建立关系、移动游标是三个独立动作；
- 系统可以建议整理，但不能静默改写 Agent 的逻辑。

### 3.2 记录判断，不复制终端

黑板主体应该保存会改变判断或后续决策的信息。工具调用属于原始活动，默认进入独立的活动层，并可由 Agent 提升为逻辑节点。

```text
原始活动：curl /api/users → 200 + JSON
逻辑节点：匿名请求可读取用户列表
```

前者用于追溯，后者用于思考和恢复。

### 3.3 当前节点是游标，不是父节点

Agent 位于节点 A 时创建节点 B，不能自动推断 A 是 B 的逻辑父节点。

系统只可以记录：

```text
cursor: A → B
```

只有 Agent 明确声明时，才建立：

```text
A --supports--> B
```

### 3.4 恢复现场，不指定行动

上下文恢复内容应该回答：

- 当前节点是什么；
- 当前节点周围有哪些直接关系；
- Agent 最近经过哪些节点；
- 哪些问题仍然开放；
- 最近一次压缩时发生了什么。

它不应该只输出“下一步从某节点继续”。同一块黑板可以支持多种合理行动，决定权应留给 Agent。

### 3.5 宽进严出

探索阶段允许低成本记录不确定内容；形成正式结论时再要求证据和置信状态。

- 普通节点可以没有边、没有状态、没有置信度；
- 猜测允许随后被反驳；
- 正式发现应至少有一条 `supports` 或 `proves` 关系；
- 系统提示不完整性，但不阻止 Agent 继续探索。

## 4. 三层黑板模型

### 4.1 逻辑层（Logic Graph）

由 Agent 主动维护，是黑板的主要内容。

包括：

- 节点：目标、观察、猜测、问题、行动、结果、发现、提示、摘要；
- 边：相关、派生、支持、反驳、依赖、证明；
- 节点状态：可选，用于表示开放、确认、否定、暂缓等语义。

逻辑层回答：“Agent 目前知道什么，这些信息之间有什么关系？”

### 4.2 游标层（Attention / Cursor）

记录每个 Agent 的注意力位置与移动历史。

包括：

- 当前节点；
- 上一个节点；
- 移动时间；
- 移动原因；
- 最近访问轨迹；
- 当前会话和 Agent 身份。

游标层回答：“Agent 现在在哪里，刚才从哪里来？”

游标移动不创建逻辑边。UI 可以把最近轨迹画成独立的临时高亮线。

### 4.3 活动层（Raw Activity）

保存工具调用、命令输出、文件读取和网络请求等原始活动。

活动层默认：

- 折叠显示；
- 不参与逻辑布局；
- 不计入逻辑节点统计；
- 支持脱敏、去重、截断和保留期限；
- 可以通过 `promote` 提升成逻辑节点。

活动层回答：“这个判断最初来自哪次操作？”

## 5. 概念数据模型

所有实体都使用稳定、不可重复的 ID，推荐 ULID。时间使用 UTC ISO 8601 或毫秒时间戳。

### 5.1 Board

```json
{
  "id": "board_01J...",
  "title": "内部 API 安全审计",
  "schemaVersion": 2,
  "createdAt": "2026-10-20T05:00:00.000Z",
  "metadata": {}
}
```

### 5.2 LogicNode

```json
{
  "id": "node_01J...",
  "kind": "hypothesis",
  "title": "管理接口可能遗漏统一鉴权",
  "body": "读接口匿名返回 200，但写接口返回 403。",
  "state": "open",
  "confidence": 0.65,
  "tags": ["auth", "api"],
  "location": {
    "path": "src/api/admin.ts",
    "line": 142
  },
  "createdBy": "agent:primary",
  "createdAt": "2026-10-20T05:10:00.000Z",
  "updatedAt": "2026-10-20T05:10:00.000Z"
}
```

只有 `id`、`kind`、`title`、`createdAt` 必填。其他字段均为可选增强信息。

### 5.3 LogicEdge

```json
{
  "id": "edge_01J...",
  "from": "node_01J_A",
  "to": "node_01J_B",
  "relation": "supports",
  "label": "匿名响应与鉴权缺失一致",
  "createdBy": "agent:primary",
  "createdAt": "2026-10-20T05:12:00.000Z"
}
```

边允许多重关系。同一对节点可以同时存在 `related-to` 和 `supports`，但 UI 默认合并显示。

### 5.4 CursorEvent

```json
{
  "id": "cursor_01J...",
  "agentId": "agent:primary",
  "from": "node_01J_A",
  "to": "node_01J_B",
  "reason": "开始验证该猜测",
  "sessionId": "session_01J...",
  "at": "2026-10-20T05:15:00.000Z"
}
```

当前节点通过每个 Agent 最新的 `CursorEvent` 推导，不依赖可损坏的旁路状态文件。

### 5.5 ActivityEvent

```json
{
  "id": "activity_01J...",
  "agentId": "agent:primary",
  "tool": "Bash",
  "summary": "curl GET /api/admin/users",
  "input": "<redacted>",
  "output": "HTTP 200 ...",
  "status": "success",
  "linkedNodeIds": ["node_01J_A"],
  "at": "2026-10-20T05:16:00.000Z"
}
```

### 5.6 Checkpoint

Checkpoint 是恢复锚点，不是逻辑流程节点。

```json
{
  "id": "checkpoint_01J...",
  "agentId": "agent:primary",
  "cursorNodeId": "node_01J_B",
  "summary": "已确认读接口行为异常，正在验证中间件差异。",
  "openNodeIds": ["node_01J_B", "node_01J_C"],
  "at": "2026-10-20T05:30:00.000Z"
}
```

## 6. 内置类型与开放扩展

### 6.1 建议内置节点类型

| kind | 含义 | 是否带工作流约束 |
|---|---|---|
| `start` | 黑板入口或任务来源 | 否 |
| `goal` | 想解决的问题或目标 | 否 |
| `intent` | Agent 当前打算做的事 | 否 |
| `observation` | 直接观察 | 否 |
| `fact` | 经确认、可复用的信息 | 否 |
| `hypothesis` | 尚待验证的解释 | 否 |
| `question` | 开放问题 | 否 |
| `action` | 已执行或准备执行的动作 | 否 |
| `result` | 某次动作的结果 | 否 |
| `finding` | 形成的正式发现 | 仅建议证据完整 |
| `hint` | 卡点、联想或后续方向 | 否 |
| `summary` | 人工或 Agent 生成的局部摘要 | 否 |
| `note` | 不适合其他类型的自由记录 | 否 |

允许自定义 `kind`。未知类型在 UI 中使用中性色，不拒绝写入。

当前的 `vuln` 可以作为 `finding` 的预置别名，`compact` 迁移为独立的 `checkpoint` 事件。

### 6.2 建议内置关系

**方向约定：边读作 “`from` `<relation>` `to`”。** `blackboard link <from> <to> --rel X` 与界面标签、Digest 箭头一致。主动语态的关系（`supports`、`proves`）以前提/证据为 `from`；被动语态的关系（`derived-from`、`depends-on`、`caused-by`）以结论/结果为 `from`。

| relation | 读法（from … to） |
|---|---|
| `related-to` | 默认弱关系 |
| `derived-from` | from 派生自 to（结论 → 前提/观察） |
| `supports` | from 支持 to（证据 → 论断） |
| `contradicts` | from 反驳 to |
| `depends-on` | from 依赖 to |
| `proves` | from 直接证明 to |
| `caused-by` | from 由 to 导致（结果 → 原因） |
| `refines` | from 补充或缩小 to 的范围 |
| `duplicates` | from 与 to 表达重复信息 |
| `supersedes` | from 取代 to |
| `resolves` | from 解决 to |

Lint 的“结论缺证据”检查据此判断：入边 `supports`/`proves`，或出边 `derived-from`/`caused-by`，都算有证据。

允许自定义关系。系统可以对已知关系提供颜色、方向和线型，但不能拒绝未知关系。

## 7. Agent 交互协议

### 7.1 基本原则

Agent 只在信息值得留给未来自己或人类时写黑板。以下情况建议记录：

- 判断发生变化；
- 新分支出现；
- 获得可以支撑结论的观察；
- 一个猜测被确认或否定；
- 当前工作位置发生明显切换；
- 即将发生上下文压缩；
- 需要把卡点留给后续会话或其他 Agent。

以下内容默认不进入逻辑层：

- 无信息量的命令成功提示；
- 重复输出；
- 安装日志；
- 与当前判断无关的工具噪声；
- 尚未经过 Agent 判断的原始响应。

### 7.2 建议 CLI

```bash
# 新建节点；默认不建立边，也不移动游标
blackboard node add observation "匿名访问 /api/admin/users 返回 200"

# 新建并进入节点
blackboard node add hypothesis "管理读接口可能遗漏鉴权" --enter

# 与当前节点建立弱关系，但不把当前节点设为结构父节点
blackboard node add question "其他读接口是否同样遗漏鉴权" --relate-here

# 明确建立逻辑关系
blackboard link <observation-id> <hypothesis-id> --rel supports

# 移动 Agent 游标，不创建逻辑边
blackboard cursor <node-id> --reason "开始验证该猜测"

# 查看当前节点与局部邻域
blackboard here

# 将原始活动提升为逻辑节点
blackboard promote <activity-id> --kind observation --title "……"

# 创建恢复检查点
blackboard checkpoint --summary "……"
```

为保持兼容，现有命令可以映射为简写：

```text
blackboard goal    → blackboard node add goal
blackboard intent  → blackboard node add intent
blackboard fact    → blackboard node add fact
blackboard vuln    → blackboard node add finding --tag vuln
blackboard hint    → blackboard node add hint
blackboard focus   → blackboard cursor
blackboard compact → blackboard checkpoint
```

### 7.3 明确禁止的隐式行为

- 创建 `intent` 后自动切换游标；
- 因为当前游标在 A，就自动把新节点设为 A 的子节点；
- 根据节点类型自动改变其他节点状态；
- 根据时间顺序推断逻辑关系；
- 将工具成功等同于事实成立；
- Digest 自动选择并命令 Agent 执行唯一下一步。

## 8. 当前节点与轨迹语义

### 8.1 当前节点

每个 Agent 在每块黑板上最多有一个当前节点，也可以为空。

```text
current(boardId, agentId) = latest CursorEvent.to
```

移动到同一节点仍可记录事件，用于表达“重新回到这里”。

### 8.2 最近轨迹

最近轨迹是游标事件序列，不是逻辑边：

```text
n12 → n18 → n21 → n18 → n43
```

UI 默认展示最近 5～10 次移动；用户可以隐藏轨迹或展开完整历史。

### 8.3 多 Agent

每个 Agent 拥有独立游标：

```text
agent:primary   → n43
agent:research  → n18
agent:review    → n72
```

UI 使用不同颜色或头像显示多个当前节点。Agent 可以读取其他 Agent 的位置，但移动自己的游标不会影响别人。

实现上，CLI 的默认身份取自 `BLACKBOARD_AGENT`（缺省为 `agent:primary`），逐条命令可用 `--agent` 覆盖；并行的 Agent 只要各设一个名字就不会共用游标。查看器把 `agent:primary` 渲染为“当前”，其余 Agent 的名字标在各自所在的卡片上。

## 9. Digest 与上下文恢复

Digest 的目标是恢复现场，不是总结整个数据库。

建议结构：

```markdown
# blackboard 黑板恢复

## 当前节点
- [n43] hypothesis：管理读接口可能遗漏鉴权

## 当前邻域
- [n31] observation --supports--> [n43]
- [n43] --related-to--> [n47] question
- [n52] observation --contradicts--> [n43]

## 最近轨迹
- n12 → n31 → n43 → n52 → n43

## 开放节点
- [n47] question：其他读接口是否同样遗漏鉴权
- [n61] hypothesis：网关与应用层策略不同

## 最近检查点
- 已验证匿名读取，正在比较中间件挂载差异
```

恢复选择顺序：

1. 当前节点；
2. 当前节点一跳邻域；
3. 最近游标轨迹；
4. 明确标记为开放的节点；
5. 最近检查点；
6. 必要时再加载更远邻域。

Digest 不输出“必须从某节点继续”。如果需要建议，应放在独立的可选区域并标明为推测。

## 10. 可视化设计

目标视觉形态是持续增长的横向逻辑黑板：整体像探索地形，局部像可阅读的卡片网络。

默认不是“把全部数据缩进一个屏幕”，而是显示可行动的当前现场。界面提供四种互不改写数据的投影视图：

```text
当前现场：当前节点 + 两跳邻域 + 目标 + 开放节点 + 最近内容
逻辑图：只显示已经建立逻辑关系的节点
时间线：按创建时间排列节点，不把逻辑边混入主要阅读路径
全部：完整节点集合；孤立节点使用紧凑网格，不拉长主图
```

这些视图仅改变观察范围，不生成关系、不改变游标、不修改节点。

### 10.1 视觉层级

| 缩放级别 | 展示内容 |
|---|---|
| 极远 | 节点密度、颜色分布、主要连接方向 |
| 远 | 节点类型色点、分支轮廓、当前节点光环 |
| 中 | 窄卡片、ID、短标题、主要关系 |
| 近 | 完整标题、状态、置信度、标签、局部关系 |
| 详情面板 | 正文、来源、文件位置、活动证据、完整上下游 |

### 10.2 当前节点表现

当前节点必须比节点类型更醒目：

- 外圈光环或缓慢脉冲；
- 独立的“当前”标记；
- 小地图中可见；
- 最近轨迹使用渐隐高亮；
- `定位当前节点` 是一级操作。

高亮不能修改节点本身的颜色，以免混淆类型语义。

### 10.3 三层显示开关

界面提供：

```text
[逻辑节点] [逻辑关系] [Agent 轨迹] [原始活动] [检查点]
```

默认打开逻辑节点、逻辑关系和当前游标；原始活动默认关闭或聚合。

### 10.4 布局

默认布局可以保持左到右的逻辑深度，但不假定图是树。

需要支持：

- 多父节点；
- 跨列长边；
- 回跳边和循环；
- 游离节点；
- 局部固定位置；
- 按时间、逻辑深度、Agent 或节点类型切换布局；
- 只重排新增局部，避免全图每次跳动。

### 10.5 大图性能

目标：普通桌面环境下，10,000 个逻辑节点仍可完成缩放、平移和定位。

实现原则：

- Canvas 或 WebGL 渲染；
- 视口裁剪；
- 多级细节；
- 布局结果缓存；
- 增量接收事件，不在每次变化时发送完整图；
- 局部邻域按需加载；
- 小地图使用聚合数据而非完整卡片。

---

## 11. 可选捕获与信息安全

Hook 不是 blackboard 的主路径。主路径是 Agent 在决策、有效结果、方向切换和交接时显式调用读写命令。只有使用者主动安装 Hook 时，系统才捕获原始活动；Hook 可以完整卸载且不影响逻辑黑板。

原始活动可能包含 Token、Cookie、密码、连接串、个人数据和内部源码。自动捕获必须默认经过以下流程：

```text
工具事件
  → 是否记录
  → 敏感字段脱敏
  → 截断与摘要
  → 去重
  → 写入活动层
  → Agent 决定是否提升到逻辑层
```

最低要求：

- 常见密钥和认证头脱敏；
- 可配置工具白名单与黑名单；
- 单次操作支持 `no-record`；
- 逻辑导出默认不包含活动原文；
- 导出前给出敏感内容扫描结果；
- 活动层可设置保留期限；
- 节点标题也要经过基础密钥检测。

## 12. 持久化与事件协议

### 12.1 事件是唯一事实源

建议事件类型：

```text
board.created
node.created
node.updated
edge.created
edge.deleted
cursor.moved
activity.recorded
activity.promoted
checkpoint.created
board.reset
```

每条事件包含：

```json
{
  "eventVersion": 1,
  "eventId": "event_01J...",
  "type": "cursor.moved",
  "boardId": "board_01J...",
  "actorId": "agent:primary",
  "at": "2026-10-20T05:15:00.000Z",
  "payload": {}
}
```

当前实现里 `edge.deleted` 与节点删除都落成同一个 `remove` 事件：`{"op":"remove","kind":"node"|"edge","id":…,"by":…}`。回放时它让节点（连同关联关系）或关系从图上消失；日志不删除任何历史。人在查看器里写入的节点带 `author: "human"`，修改带 `updatedBy`。

### 12.2 可重建性要求

删除所有派生缓存后，仅通过事件日志必须能够恢复：

- 全部节点与边；
- 每个 Agent 的当前游标；
- 标题和配置；
- 检查点；
- ID 不重复。

ID 不能依赖单独的可变计数器。索引、快照和 `state.json` 都只能是可删除缓存。

### 12.3 写入原子性

- 单个领域动作对应一条完整事件；
- 使用稳定唯一 ID；
- 文件锁超时只能失败，不能删除仍有效的锁；
- 尾部损坏时截断到最后一个完整换行，再继续追加；
- 定期生成可验证快照，但快照不能取代事件日志。

## 15. 验收标准

### Agent 自由度

- 任意节点类型可以连接任意节点类型；
- 创建节点不会隐式移动游标；
- 移动游标不会隐式创建逻辑边；
- 未知节点类型和关系可以保存并显示；
- 系统不依据简单启发式命令 Agent 执行某个下一步。

### 恢复能力

- 删除缓存后可从事件完整恢复；
- 上下文恢复后能看到当前节点、一跳邻域和最近轨迹；
- 多个 Agent 的位置互不覆盖；
- Checkpoint 创建后立即出现在恢复摘要中。

### 可视化

- 当前节点在任何缩放级别都可辨识；
- 可单独显示或隐藏逻辑关系、轨迹和活动；
- 支持循环、多父节点和跨列边；
- 10,000 节点下平移、缩放和定位仍可用。

### 安全与质量

- 自动记录默认脱敏；
- 导出默认排除原始活动正文；
- 非法内置状态给出错误，但自定义类型通过明确扩展字段保存；
- 并发写入不产生重复 ID 或被覆盖节点；
- 核心事件回放、游标和迁移具有自动化测试。

## 16. 设计判断清单

新增功能时，用以下问题判断它是否符合黑板思想：

1. 它是在帮助 Agent 记录，还是在规定 Agent 怎么思考？
2. 它是否把游标移动误当成逻辑关系？
3. 它是否把原始工具日志误当成语义事实？
4. 它是否允许不确定、反驳和回跳？
5. 它是否能仅从事件日志恢复？
6. 它是否在大图上仍然可读和可操作？
7. 它是否会把敏感信息无提示地带入导出文件？
8. 它是在恢复现场，还是在替 Agent 决定下一步？

如果一个设计让图更整齐，却让 Agent 必须为了图而改变自然探索方式，应优先修改这个设计。

---

## 17. 最终原则

```text
允许自由探索，但不丢失现场。
允许逻辑混乱地生长，但提供清晰的局部观察。
允许 Agent 回跳，但保留移动轨迹。
允许原始活动被追溯，但不让日志淹没逻辑。
允许系统提出建议，但不替 Agent 决定。
```

`blackboard` 的成功标准不是图是否符合预设流程，而是任意时刻打开黑板，人或 Agent 都能回答：

> 我们已经想过什么？这些判断为什么成立？现在正在看哪里？接下来有哪些可能方向？
