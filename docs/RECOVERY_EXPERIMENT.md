# 恢复对照试验：方案

> 对应 [发展方向](ROADMAP.md) 第 1 项。本文在试验开始前写定，结果出来后不改动判定规则；需要调整时另起一版并注明原因。

## 要回答的问题

**新 Agent 拿到黑板后，能不能接住原来的工作？图结构（关系）相比普通交接摘要和单纯的节点列表，是否带来可观察的差别？**

这是小规模探索性试验：两三个真实任务，目的是发现问题、决定后续投入，不产出通用“恢复分”。

它和 `scripts/evaluate-recovery.mjs`（尚未合并）不同：那个脚本检查 `context` 投影是否覆盖必需的内容，证明投影正确；本试验检查读到投影的 Agent 能否据此正确回答，证明投影有用。

## 不做什么

- 不建评分平台、排行榜或长期指标看板。
- 不用合成黑板的结果代替真实任务的证据。
- 不让 LLM 生成或改写恢复材料；三组材料都由现有投影或任务 Agent 自己写的检查点摘要构成。
- 不改内核，不写任何黑板：准备脚本只读事件日志。

## 语料

- 两三个真实长任务（代码研究、审计或调试），在 Claude Code 或 DSH 上照常完成，保留完整黑板。
- **执行任务的 Agent 不知道之后要考恢复**，记录方式按平时进行。
- 任务中至少有一个检查点被用作截断点 T；“中断续接”还需要更早的检查点 S。
- 原始黑板不进版本库。只有脱敏后的语料才可以作为测试数据提交，并注明脱敏方式。

## 两种恢复情形

| 情形 | 恢复者读到的材料 |
| --- | --- |
| 首次接手 | 日志截到 T 时点的完整材料 |
| 中断续接 | S 时点的材料（模拟中断前已有的上下文），再加 S→T 的增量 |

## 三组对照

| 组 | 材料 | 来源 |
| --- | --- | --- |
| A 交接摘要 | T（续接时为 S 和 T）检查点的摘要原文 | 任务 Agent 自己写的 `checkpoint --summary` |
| B 仅节点 | C 的投影去掉一切关系信息：`relations`、邻域里的关系与方向、结构变化里的关系增删 | 同一份事件日志 |
| C 节点 + 关系 | 完整事件日志的 `context` 投影 | 同一份事件日志 |

- B 与 C 包含**完全相同的节点**，只差关系，这样比较的才是图结构本身。不能用“去掉关系事件再回放”来做 B：当前焦点的邻域靠关系选出，那样 B 会少掉一批节点，比较就混入了“信息量不同”。
- C 按给定 token 预算投影，B 由它派生，因此 B 总是更小；两组的实际大小都记在清单里。
- `context` 投影本身包含检查点摘要，所以 A 的内容也出现在 B、C 里。A 对 C 回答的是“图在摘要之外有没有增益”，不是两种互斥材料的比较。摘要原文提到关系时保留不动，B 只去掉结构化的关系字段。
- A 不截断，因为摘要是原作者写的；它的实际大小同样记在清单里，分析时一并报告。
- 清单中的 token 数沿用投影自己的估算（JSON 长度 ÷ 4），对中文明显偏低。比较材料大小时以字符数为准。
- 固定恢复模型、提示词和问题；三组只换材料。

## 准备材料

```bash
node scripts/recovery-experiment.mjs prepare --board <项目根> --at <检查点 T> --out <输出目录>
node scripts/recovery-experiment.mjs prepare --board <项目根> --at <检查点 T> --since <检查点 S> --out <输出目录>
```

输出目录包含：

- `A-summary.md`、`B-nodes.json`、`C-graph.json`：交给恢复者的三组材料。B、C 是 `context` 的 JSON 投影，也是 CLI 默认输出和适配层实际读取的格式；续接时分为 `interrupted`（S 时点）和 `since`（S→T 增量）两部分，各用同一预算。
- `manifest.json`：截断位置、事件前缀的哈希、T 时存在的节点（类型、状态、可信度）、各组大小和记录成本。答题核对只用它，不再读原始黑板。

截断严格按事件位置进行，T 之后的任何事件都不会进入材料。

## 出题

- 出题人**只看截至 T 的日志**，不看任务后来的进展。
- 每个任务 8–15 题，覆盖：为什么做了某个决定、某个结论的证据是什么、哪些假设还没验证、哪些方向被放弃及原因、下一步还缺什么证据。
- 至少三分之一的题目答案在 T 时**没有被记录**，标准答案是“未知”。
- 题目文件 `questions.json`：

```json
[
  { "id": "q1", "text": "为什么放弃了缓存方案？", "evidence": ["F3", "H2"] },
  { "id": "q2", "text": "鉴权绕过是否已复现？", "expected": "unknown" }
]
```

`evidence` 是能支持标准答案的节点 ID（截至 T 存在），`expected: "unknown"` 表示截至 T 没有答案。

## 答题格式

恢复者对每题给出答案、引用的节点 ID，以及自己的把握：

```json
[
  { "question": "q1", "arm": "C", "answer": "……", "cites": ["F3"], "stance": "fact" },
  { "question": "q2", "arm": "C", "answer": "未记录", "cites": [], "stance": "unknown" }
]
```

`stance` 取 `fact`（确定）、`guess`（推测）或 `unknown`（材料里没有）。答案内容是否正确由人判定，写入可选字段 `correct: true|false`。

## 指标

```bash
node scripts/recovery-experiment.mjs check --manifest <输出目录>/manifest.json --questions questions.json --answers answers.json
```

按组汇总，能机械核对的都不交给模型判断：

| 指标 | 含义 | 核对方式 |
| --- | --- | --- |
| 答对 | 人工判定正确的题数 | `correct` 字段 |
| 引用有效 | 引用的节点在 T 时存在 | 对照清单 |
| 命中证据 | 引用至少包含一个标准证据节点 | 对照 `evidence` |
| 恰当回答未知 | 标准答案为未知时回答 `unknown` | 对照 `expected` |
| 漏答 | 有答案却回答 `unknown` | 对照 `expected` |
| 猜测说成事实 | 以 `fact` 回答，但引用的节点都是猜测性的（`suspected`，或 hypothesis / question 类型） | 对照清单 |
| 恢复成本 | 材料大小、恢复者补读次数和耗时 | 清单与运行记录 |
| 记录成本 | 截至 T 的节点、关系、修改、检查点事件数和文字量 | 清单 |

## 判定规则（试验前写定）

样本小，只看方向，不做显著性检验。

- **C 明显优于 B**（多数任务上答对或命中证据更多，猜测说成事实不增加）：关系对恢复有贡献，继续降低记录关系的成本，并在 Skill 中引用这个证据。
- **C 与 B 相当**：关系主要服务于人读，不是恢复的主要来源；恢复方向优先改进节点与检查点摘要的质量。
- **A 不明显落后于 B、C**：图结构对恢复的贡献有限，重心转向“记录更便宜”或“人更读得懂”，并重新审视 `context` 的内容取舍。
- **所有组在“恰当回答未知”上都差**：问题在恢复提示或投影的表达方式，不在记录本身，先改投影中对缺失信息的呈现。

任何结论都要附上记录成本：一个组恢复更好，但记录成本高出数倍，不能直接算作更好。

## 试验前已知的投影问题

准备脚本在演示黑板上试跑时发现，记在这里，试验期间不修改：

- **中文的 token 估算偏低。** `context` 按 JSON 长度 ÷ 4 估算，中文大约一字一 token，实际占用可能是估算的数倍。中文黑板的“预算”因此比名义值宽松，比较时以字符数为准。
- **Markdown 输出缺少关系。** `main` 上的 `context --markdown` 不渲染 `relations`，尚未合并的改动已经补上。试验统一使用 JSON 投影，不受影响。

## 记录与公开

- 每个任务保存：清单、题目、三组答案、人工判定和一段文字观察。
- 结论写回 [发展方向](ROADMAP.md)，并标明样本数与局限。
- 发现的投影缺陷单独记录，不在试验期间修改投影，避免同一轮试验里材料不一致。
